Why does my project have two repositories?

A new project is set up nested: the product sits in a subfolder with a clean repository of its own — the one that goes public when you ask — and the folder around it holds your planning documents in a private repository that never gets a remote. Someone landing on the published repository sees the product, not your reasoning. /close commits both.

An existing flat project is converted when setup runs on it. Setup shows the plan file by file and runs it on your yes, telling the two shapes apart by whether your repository already has a remote: where it has none, the product's files move into a new inner repository; where it has one, the wrap keeps that repository whole as the inner one and creates the outer around it, moving the planning documents up and changing nothing that points at the published repository. Declining stops setup with the project unadopted. What tells you it worked is the Visibility line in your project's CLAUDE.md naming both repositories.

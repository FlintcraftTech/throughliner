Can Claude explain the code as it writes it?

You will meet this at setup, in the message offering a reply style for the project. It names two: Throughliner Brevity, the recommended one, which keeps Claude's replies short and led by the decision; and Throughliner Code Notes, which is the same with one addition. Say which you want, and the choice is written as one line in the project's own settings file; it takes effect at the next session. With Code Notes, after each piece of code written or changed — in a build run, after each item — Claude adds a short block headed Code notes: two or three plain-English points on why the code is the way it is, what it connects to, and what to look at to see it working. The block comes after the result, goes in the conversation and never into your files, and a build run does not pause for it; you read it afterwards. Runs are longer for it. What tells you it worked: the first reply after a piece of code ends with a Code notes block.

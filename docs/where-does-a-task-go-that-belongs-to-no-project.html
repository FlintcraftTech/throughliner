Where does a task go that belongs to no project?

To the queue of the project that keeps your task-list note, the one your Task list: line names, so it reaches your Tasks queries like every other task. You meet this in any chat, in any command, when you name a task: say it is a general task, or that it belongs to no project, and Claude shows you the capture's text and sends it to that project on your yes, exactly as a capture is sent between projects. Where the task obviously has nothing to do with the project you are in, Claude asks once whether to put it in your general tasks, and files it in the current project on a no. A task you name with no word either way, bearing on the project, is filed where you are, as before. Setup's task-list question says the note must sit inside a Throughliner project with a queue, since that queue is where these tasks land, and records that project so a send can find it; a note in a folder that is not a Throughliner project is reported as a fact, and the send is refused like any send to a project Claude has no address for. What tells you it worked: Claude's one line naming the project and the capture, and the task in your queries once that project's planning has run, or at once in Obsidian, since the capture already carries the task line.

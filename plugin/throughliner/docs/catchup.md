# /catchup

**/catchup is for a user coming back after time away.** It says where the project's goals stand and what has changed for the user since they were last here, in a few lines, and re-runs the return checks an opening runs. It moves nothing, and files only what those checks file: a due cycle's capture.

**Read:** SPEC's Goals section; both queue sections; the clock; the `LOG/index.md` lines dated within the fourteen days before the clock's date (the previous month's index where the window reaches into it), and for each build record among them the record written when that item was kept; the cycles doc through `cycles_state`, due-ness computed as opening.md computes it; the installed version against the one this chat opened on; and the clock against the opening's date line. Where a session already opened in this chat, read only what is missing.

**A goal is reached** where its line is ticked or its "reached when" clause names something the record, the cycles doc or the queue shows holding, and heading otherwise.

**The brief** opens on the first goal's line, with nothing before it, in this order:

1. One line per goal in SPEC's order, reached or heading, with what its test shows now in plain words.
2. The what-changes lines, as build.md's run's-end section defines them, for the items built in the fourteen days before the clock's date. Where nothing was built in the window, one line says so.
3. Three lines: what a build would do next, what is waiting on the user, what is held on a date, each "nothing" where empty.
4. One line per return check that found something, in the opening's own words, and none for a check that found nothing.
5. The one offer to walk through any of the changes, one message each.

> **Weekly release every Wednesday** — heading: the last release was on the second, and nothing has shipped on the two Wednesdays since.
>
> **Search across notes.** You asked for "one box that finds anything I wrote". Typing in the box at the top now searches every note, so nothing has to be found by scrolling.
> **Dark theme.** "My eyes hurt at night." The switch is in settings, and the app remembers it.
> Three smaller fixes also went in.
>
> Next build: tags on notes. Waiting on you: nothing. Held on a date: the launch post, until the sixteenth.
>
> Want me to walk you through any of these?

**Out by rule:** slugs, file names, rationale, counts beyond the three lines, and anything not asked about.
